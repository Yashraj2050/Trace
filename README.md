## Overview

Trace combines user-entered and document-derived sustainability data into a persistent user experience. It uses Next.js for the application layer, Supabase for authentication and database services, and the Google Gemini API for document analysis, recommendations, and conversational assistance. 

Carbon estimates derived from uploaded documents are generated by Gemini's multimodal analysis, rather than calculated through a proprietary deterministic emissions model.

## Core Workflows

### 01 — Document Analysis
Uploaded files are posted to `/api/ocr`, where the Gemini API analyzes the document (e.g., energy bills) and returns structured information including estimated carbon impact, confidence levels, and descriptive details. When the Gemini API is unavailable or unconfigured, the system gracefully falls back to a deterministic mock response.

### 02 — Carbon Tracking
Users can log carbon impact via the `carbon_entries` table. Entries are associated with a specific user profile and persisted in Supabase.
- **Categories:** transport, energy, food, shopping, travel
- **Sources:** manual, calculator, ocr, import

### 03 — Prediction
The `/api/predictions` endpoint fetches historical carbon entries from the database and computes a basic mathematical linear regression (slope and intercept) to plot future trajectories. 

### 04 — Recommendations
The `/api/recommendations` endpoint utilizes recent user footprint data as context to generate personalized sustainability suggestions via Gemini, with a static list of recommendations serving as a fallback.

### 05 — Sustainability Coach
The `/api/coach` endpoint is a conversational route that prompts Gemini to act strictly as a sustainability coach, answering user questions about environmental impact.

## Authentication

Trace relies on Supabase SSR (Server-Side Rendering) authentication. Secure API routes (such as `/api/predictions`) retrieve the authenticated Supabase user and actively return HTTP `401 Unauthorized` when a valid session is absent. 

## Data Model

The application leverages a relational PostgreSQL schema:
- **`profiles`:** Associated 1:1 with `auth.users` to store user metadata (sustainability score, streak days).
- **`carbon_entries`:** Associated with `profiles` via `user_id` to log distinct footprint events.

## API Reference

| Method | Endpoint | Purpose | Auth |
|---|---|---|---|
| POST | `/api/ocr` | Gemini-powered document/image analysis | Unauthenticated |
| GET | `/api/predictions` | Historical carbon prediction via linear regression | Required (Supabase) |
| GET | `/api/recommendations` | Personalized recommendations | Required (Supabase) |
| POST | `/api/coach` | Sustainability chat | Unauthenticated |

## Limitations

- Carbon estimates from document analysis are Gemini-generated estimations rather than calculated through a proprietary emissions engine.
- OCR and document interpretation depends entirely on external Gemini API connectivity.
- Static mock fallbacks exist for AI-powered workflows when external APIs are unavailable.
- Historical prediction utilizes a basic linear regression calculation rather than machine learning.
- No custom PyTorch/TensorFlow carbon model is present.
- No custom OCR model is present.
- No external deterministic carbon-factor API (e.g., Climatiq) is integrated.

## Roadmap

## Setup

```bash

```

Configure `.env.local`:
```env
NEXT_PUBLIC_SUPABASE_URL=...

```
